# Диагностика таро — 5 ноября 2026

## Подтверждённый дефект

В Studio одной и той же игре и одному клиенту передавались одинаковые asset ID двумя способами:

| Таро | Строка rbxassetid в PreloadAsync | ImageLabel с этим Image в PreloadAsync |
|---|---|---|
| Луна 90050084021940 | Failure | Success, IsLoaded=true |
| Часы 112005936945493 | Failure | Success, IsLoaded=true |
| Нить 71467474698283 | Failure | Success, IsLoaded=true |

Это воспроизводимая разница путей разрешения ресурсов, а не доказательство блокировки изображений. Старый WarmTarot принимал Failure как повод советовать проверить права/модерацию, хотя те же рисунки непосредственно в ImageLabel работали. Такой диагноз был преждевременным.

## Исправление

Общая предзагрузка Assets.PreloadAll создаёт временные ImageLabel и передаёт их ContentProvider вместо голых строк. Начальная предзагрузка Client использует тот же метод; повторные вызовы не запускают её заново. Временные объекты удаляются по завершении. Статусы доступны через Assets.GetLoadReport. Ошибки теперь описывают фактический сбой загрузки без утверждения о его причине.

После перезапуска Play: 14/14 Success (12 таро + колода + портреты). Проверены все 12 рисунков на тестовой видимой сетке — IsLoaded=true. В настоящем шкафу после прокрутки видимые Роза, Страж, Солнце, Луна и Башня отображаются. У невидимых элементов прокручиваемой полки IsLoaded может оставаться false до появления на экране, даже при успешной предзагрузке; само по себе это не отказ доступа.

## Что проверено по правам

- Владельцы проверенных изображений и игры совпадают: Rozhok_serj, user 11928783962; universe 10774770146, place 97394667385511.
- Проверенные типы ассетов — Image (1), а не ошибочно используемые Decal ID.
- Неавторизованный HTTP-запрос AssetDelivery возвращает 403 `User is not authorized to access Asset` как для таро, так и для работающей колоды. Такой запрос НЕ доказывает отсутствие разрешений у опубликованной игры.
- Публичные thumbnails всех этих файлов показывают PrivateImage; это также не свидетельствует о блокировке владельца.
- По официальной документации собственные ассеты доступны в собственных играх независимо от privacy setting: https://create.roblox.com/docs/projects/assets/privacy
