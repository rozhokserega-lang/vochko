# Общий рейтинг бесконечного режима

Проект Supabase: `ejjbkxtnjfpjbppcvijm`. Миграция: `supabase/migrations/20261101_vochko_leaderboard.sql` (применена через SQL Editor после явного подтверждения владельца).

Вход: главное меню → «Рейтинг игроков»; дополнительная кнопка «Рейтинг» на экране завершения бесконечного забега. Показываются первые 100 игроков, свой результат и место даже за пределами первой сотни. Порядок: число побеждённых врагов, затем очки, затем более раннее достижение результата. Один лучший результат на сохранённый профиль.

## Отправка и сохранения

При начале нового бесконечного забега создаётся случайный идентификатор забега, сохраняемый вместе с игрой. После поражения результат попадает в очередь и отправляется в Supabase. Временный сбой не удаляет результат; повторная попытка происходит при открытии рейтинга, обновлении таблицы или восстановлении подключения. Повторный запрос с тем же результатом безопасен и не создаёт дубль; изменение уже завершённого результата отклоняется сервером.

При открытии рейтинга переносится ранее сохранённый личный рекорд. Результат текущего незавершённого похода не отправляется вместо завершённого. Личный рекорд на устройстве продолжает работать независимо от доступности сервера.

## Доступ

Устройство хранит случайный UUID профиля и 256-битный секрет отдельно от META и сохранённого забега (`vochko.leaderboard.identity.v1`). На сервере хранится только SHA-256 секрета. Имя не является паролем: совпадающие ники не позволяют записывать результаты в другой профиль. При очистке локальных данных или на другом устройстве это будет новый профиль; привязка к Telegram-аккаунту пока не реализована.

Таблицы `players` и `endless_runs` находятся в неэкспонируемой схеме `vochko_private`, включён RLS, у `anon`/`authenticated` нет доступа к схеме и таблицам. Браузеру разрешены только четыре RPC: регистрация своего профиля, старт своего забега, отправка своего результата и чтение ограниченной публичной таблицы. SECURITY DEFINER функции используют пустой search_path. Ник, место, победы и очки — единственные публичные данные рейтинга. Ключ `sb_publishable_…` в клиенте предназначен для публичного браузерного использования; административных ключей в проекте нет.

Сервер проверяет владельца, диапазоны значений, завершённость и однократность отправки. Это рейтинг клиентской игры: полного серверного воспроизведения партии и защиты от изменения собственного счёта через инструменты разработчика пока нет. Для соревнований с призами потребуются серверная проверка хода игры и привязка аккаунта.

## Проверки

- `npm run test:leaderboard`: интерфейс, старый рекорд, сохранённый профиль, очередь, повторная отправка, четыре ширины экрана и сообщение об ошибке; изолированные сетевые ответы.
- `npm run test:endless`: бесконечный режим и дополнительный ход.
- Сервер проверен в транзакции под ролью `anon`: кириллический ник, сортировка, выбор лучшего забега, повторная отправка, отказ при чужом секрете/профиле, отказ изменять завершённый результат и отсутствие прямого чтения приватных таблиц. Транзакция откатена; проверочные игроки не остались в таблице.
- Публичный RPC проверен через браузерный ключ, приватная схема через Data API недоступна.

Обычные автотесты блокируют сетевые запросы к боевому Supabase, чтобы фиктивные результаты не попадали в общий список. Явное `LEADERBOARD_INTEGRATION=1` снимает блокировку только для контролируемой проверки.
